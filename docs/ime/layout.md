# 配列設計 — 縦組五十音・二行配列・楷行草

> 矢立の入力面の設計。原点にある PC 配列の構造を読み解き、そこから設計原理を抽出し、
> タッチスクリーン向けの「二行（ふたくだり）配列」と、入力確度の三態「楷・行・草」を定義する。

## 1. 原器 — 縦組五十音配列（PC・使用者考案）

使用者が約 10 年使ひ込んできた自作配列。口頭の記述から再構成したものを示す。
**再構成は推定を含む——「要確認」欄を本人が確認・訂正すること。**

記述された確定点:

- 右上の `0` = あ。左に向かつて `9` = い。下に向かつて `p` = か。**縦書きコンセプト**。
- `j` で折り返し、`5` = た。
- `A` = ほ。
- `^`（前置シフト）で第二面へ: `^0` = ま、`^5` = ら、`^q` = を、`^^` = ん。
- 残りのキーは句読点等を適宜配置。
- いろは唄の平面配置は検討したが、キーボードに収まらず操作性も悪く断念（→五十音採用）。

### 再構成（推定）

第一面（無シフト）— 清音 30 字（あ〜は行）:

```
      左半面（第二の行）              右半面（第一の行）
  ［1］［2］［3］［4］［5］    ［6］［7］［8］［9］［0］   ［^］
   と   て   つ   ち   た      お   え   う   い   あ     前置
  ［q］［w］［e］［r］［t］    ［y］［u］［i］［o］［p］    シフト
   の   ね   ぬ   に   な      こ   け   く   き   か
  ［a］［s］［d］［f］［g］    ［j］［k］［l］［;］［:］
   ほ   へ   ふ   ひ   は      そ   せ   す   し   さ      （JIS。b＝濁点・v＝半濁点）
```

第二面（`^` 前置後）— ま・や・ら・わ行 ＋ ん。**や行・わ行とも五段が埋まる**
（や行に い・え、わ行に う を重複配置——地図の完全性を欠けより優先する）:

```
  ［1］［2］［3］［4］［5］    ［6］［7］［8］［9］［0］   ［^］
   ろ   れ   る   り   ら      も   め   む   み   ま     （^^＝ん）
  ［q］［w］［e］［r］［t］    ［y］［u］［i］［o］［p］
   を   ゑ   う   ゐ   わ      よ   え   ゆ   い   や
```

読み方: **紙面の見立て**である。右半面が縦書きの第一行——あ行を天から書き下ろす代はりに、
段（あいうえお）が右から左へ進み、行（あ→か→さ）が上から下へ降りる。`j`（そ）まで書き切ると
紙面の行を替へるやうに左半面へ折り返し、第二の行（た→な→は）が再び上から降りる。
第二面も同じ紙面構造の写しで、右半面に ま・や、左半面に ら・わ。ん は行にも段にも属さぬ
唯一の仮名として、シフトそのものの重ね打ち（`^^`）に住む。

この構造が与へる恩恵は明快である:

- **段は横、行は縦**といふ一貫した座標系。指は「五十音表のどこか」を常に幾何学的に知つてゐる。
- 歴史的仮名遣ひの **ゐ・ゑ が第一級のキー**を持つ（`^r`・`^w`）。現代 IME のやうに
  「うぃ」等の迂回を強ひられない。
- 前置シフトは同時押しでなく**逐次打鍵**（`^` を打つてから `0`）なので、片手でも完結する。

> **確認済み（2026-07-30 本人回答）**: ① 鍵盤は **JIS**——さ行は `:` `;` `l` `k` `j`
> （さ=`:`、折り返しの j=そ）。② 第二面は上図の通り**全スロットが埋まる**
> （やいゆえよ・わゐうゑを）。③ **濁点＝`b`・半濁点＝`v`**（後置打鍵）、
> `^j`＝括弧開・`^f`＝括弧閉ぢ等の記号は第二面に散らす（本人曰く「あまり重要ではない」）。
> ④ 最下段の残りは句読点等を適宜配置。

### 原器から抽出する設計原理

1. **縦書きの座標系** — 行（ぎゃう）の進行は「下へ」、段の進行は書字方向に従ふ。
2. **五十音の幾何学** — 配列は暗記表ではなく地図である。位置が音韻構造を表す。
3. **前置シフトの逐次性** — 同時押しを要求しない。モバイルのタップ列と等価に写せる。
4. **例外の詩学** — ん のやうな体系外の字には、体系外の場所（`^^`）を与へる。

## 2. 二行（ふたくだり）配列 — モバイル主配列

原器の紙面の見立てを、タッチスクリーンの一枚に開き直す。折り返しも前置シフトも不要になり、
**十の行キーが縦書き二行にそのまま並ぶ**:

```
 ┌─────────┬─────┬─────┐
 │  機能列  │ 第二行 │ 第一行 │      ← 画面右端が第一行（縦書きの読み順）
 ├─────────┼─────┼─────┤
 │  削除    │  は   │  あ   │
 │  ん      │  ま   │  か   │
 │  、。    │  や   │  さ   │
 │  空白    │  ら   │  た   │
 │  確定/改行│  わ   │  な   │
 └─────────┴─────┴─────┘
   （左端に地球儀キー・モード印〔楷/行/草〕・数字記号切替を細く配す）
```

- 右列（第一の行）: あ・か・さ・た・な。左列（第二の行）: は・ま・や・ら・わ。
  縦書き二行を右から読む順序そのままであり、原器の折り返し構造の写しである。
- ん は原器同様、行キーの体系外——機能列に独立のキーを持つ。
- キーは 10＋機能で、標準 12 キーより少ない。一キーが大きく、誤打鍵が減る。

### 段の所作 — 書き下ろし（スライド）

標準フリックの「中心から四方へ弾く」を捨て、**縦書きの身体感覚**に置き換へる:

1. 行キーに触れると、その行の五段が**縦一列の梯子**として指の脇に現れる
   （か→き→く→け→こ が上から下へ。指の真下を避けて左右いづれかにオフセット表示）。
2. **下へ滑らせる**と段が降りる。滑つた距離で段が量子化される（0=あ段 … 4=お段）。
   離した位置の段が採られる。あ段はその場で離す（＝タップと同じ所作）。
3. **右への逸らし**は濁点。濁点が字の**右肩**に打たれる和文の作法と同型である。
   逸らした瞬間、梯子は が行 に変はる（か行・さ行・た行・は行のみ有効）。
4. **左への逸らし**は半濁（は行→ぱ行）と小書き（や行→ゃゅょ、つ→っ、あ行→ぁ〜ぉ）。
5. 梯子は常に **5 スロット固定**。や行は や・（い）・ゆ・（え）・よ、わ行は わ・ゐ・（う）・ゑ・を と
   空きスロットを灰色で残す——位置の筋肉記憶を段の実在に優先させる。
   **ゐ・ゑ はここでも第一級**であり、わ行の 1 段目・3 段目として一動作で書ける。
   なほ原器は第二面の全スロットを埋める流儀（や行に い・え、わ行に う を重複配置）
   なので、設定でこの重複経路を梯子でも生かす選択肢を残す。

促音・拗音は合成で書く（きゃ ＝ か行 1 段目 → や行左逸らし）。長音「ー」・繰り返し記号
「ゝゞ〻」・カギ括弧は数字記号面に置く（文語では頻度が低い）。

### 遅延と確定

- 梯子の出現・追従は**端末内で 16ms 以内**（描画フレーム内）。入力エコーに網も AI も待たせない。
- 確定前の文字列はキーボード上縁の**作業帯**に出す（ホスト側 marked text は既定 OFF・
  設定で有効化した場合のみ併用——[architecture.md](./architecture.md) §5）。

## 3. 楷・行・草 — 確度の三態

矢立の中核概念。**一打が運ぶ情報量を書き手が選ぶ**。書体の三態になぞらへる:

| 態 | 所作 | 一打の意味 | 解消の主体 |
|---|---|---|---|
| **楷** | タップ＝あ段、滑りで段指定 | 完全指定の一字（従来のかな入力と等価） | 書き手 |
| **行** | タップ＝**行のみ**（段は委ねる）、滑りで随時ピン留め | 制約 `{行, 段=未定}` | 辞書・コーパス・LLM |
| **草** | 行キー群の上を**一筆で撫でる** | 経路全体が一語の制約 | LLM（将来） |

- 三態は**混在できる**。行打ちの途中で一箇所だけ滑つて段を確定してもよい
  （「はな」か「ひな」かを紛れさせたくない一字だけピン留めする）。
  入力列は一様に**制約の列**であり、楷はその全指定の特殊例にすぎない
  （[protocol.md](./protocol.md) — 現行 API の被覆検査を制約整合検査へ一般化する）。
- モード印（楷/行/草の一字）は機能列に常時表示し、タップで切替。既定は 楷、
  習熟後に 行 を促す。

### 行打ち（ぎゃううち）の例

「けふはよきてんきなり」（今日は良き天氣なり）:

```
入力（タップ 10 回のみ・滑りなし）:
  か  は  は  や  か  た  ん  か  な  ら
  ↓ 制約列: k? h? h? y? k? t? ん k? n? r?
解:
  け ふ は よ き て ん き な り   → 今日は良き天氣なり
```

- 一モーラ一タップ、フリックゼロ。標準フリックなら同文は 10 打中 8 打が方向つきフリックである
  （タップで済むのは「は」「な」だけ）。
- 行の骨格は見かけより強い制約である（かな 1 字の情報量約 5.6 bit のうち行が約 3.3 bit を担ふ）。
  骨格に合ふ**旧仮名の読み**を端末内辞書（青空文庫から収穫——[architecture.md](./architecture.md)）
  で引き、多義が残れば文節候補として提示する。T9 が英語で示した原理の、
  五十音の幾何学に基づく日本語版と言へる。
- 未解消の間、作業帯には行頭の仮名が**淡く草書調**に出て、解に至ると楷書の字面に**結晶**する。
  曖昧さを隠さず、墨が乾いてゆく様として見せる。

## 4. iPad 全鍵盤版 — 原器を硝子の上へ

iPad の横画面では原器 30＋シフト面をそのまま**軟鍵盤**として敷く（キー間隔・段差は原器準拠、
`^` は前置シフトとして同じ逐次打鍵）。物理キーボード接続時にキーボード拡張はキーイベントを
受け取れない（制約の詳細は [architecture.md](./architecture.md)）ため、**硬鍵盤対応は
本体アプリ内の稽古場エディタと将来の macOS IMKit 版**が担ふ。

全鍵盤版でも行打ちは成立する: **各行の行頭キーだけを打つ**（あ＝`0`、か＝`p`、さ＝`'`、
た＝`5`、な＝`t`、は＝`g`、ま＝`^0`、や＝`^p`、ら＝`^5`、わ＝`^t`）。原器使ひが
矢立の確度概念をそのまま持ち込める。

## 5. 捨てたものとその理由

- **12 キー標準配置** — モーラ確定入力の最適化であり、制約流には過剰な同時性を要求する。
  また 10 行を 12 キーに散らす配置は五十音の幾何学を壊す。
- **いろは配列** — 原器の検討で既に棄却されてゐる（平面に収まらず操作性が悪い）。
  文語の道具だからこそ、体系（五十音）を地図として使ふ。
- **ローマ字入力** — 子音＋母音の二打分解は行打ちと情報構造が近いが、ラテン文字の鍵盤を
  経由する必然がない。行キーは仮名そのものを刻む。
- **音声入力・手書き** — 歴史的仮名遣ひは音と綴りが乖離する（けふ/きょう）。音声からは
  旧仮名が復元できない。綴りを直接打てることが文語入力の要件である。
