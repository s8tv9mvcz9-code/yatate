## M2 — 校合の接続（T2・候補 UI）

- 既存 `BungoAPI`/`Models` を `YatateCore` へ移設（本体アプリと拡張で共有。
  アプリ側は import の付け替へのみ）。
- 変換キー→ `/convert`（明示引金・350ms デバウンス・429 静退避）。文節カード・
  縦書き候補列（Core Text）・色点・實例バッジ・区切り修正ジェスチャ
  （`merge`/`split`/`yomi_list` は T0 に既にある）。
- サーバ側小改修: 候補出典 `provenance`（[protocol.md](./protocol.md) §3、
  `rank_candidates` にチャンク列を渡す数行）と `/health` の `features` キー。
  `backend/test_contract.py` に additive キーの回帰を足す。
- 墨色三態の表示と劣化遷移（[architecture.md](./architecture.md) §7）。
- **出口条件**: ホスト任意のアプリで「けふはよきてんきなり」→候補選択→
  「今日は良き天氣なり」確定まで、手数が Android 變換タブと同等以下。

## M3 — 行打ち（制約流の実装・本設計の核心）

- Python SSOT: `KANA_INFO`・`constraint_error` を `app/kana.py` に、`constraints` 受理を
  `app/convert.py`／`backend/main.py` に（[protocol.md](./protocol.md) §2。
  `eval/test_kana.py` に境界例を追加）。
- 収穫辞書 v1: `scripts/build_ime_dict.py`（ルビ抽出・TSV・行シグネチャ索引・出典表）。
  まづ `importDynamicUserDictionary` 規模（数千語）で始め、質を見て `user.louds` 同梱へ。
- 拡張側: 行モード（タップ＝行のみ）・骨格引き（T1）・草書調の未確定表示と結晶、
  サーバ制約解消（T2・機能検出つき）。
- 稽古場 v1（本体アプリ）: 課題文写し・KSPC／確定時間／候補一発率の端末内計測、
  楷 vs 行の A/B（`scripts/eval_ab.py` と同じ流儀の比較表）。
- **出口条件**: 行打ちで課題文 3 種の KSPC が楷比で有意に下がり、誤結晶率が
  許容域（稽古場で数値を定める）に収まること。

## M4 — 深化（辞書の本格化・実験枠）

- `anco dict build` によるシステム辞書再構成（新仮名の排除・旧仮名コスト優遇）と
  `anco evaluate` での回帰。ルビ収穫の規模拡大（`MAX_BOOKS` 増）。
- zenz の文語 fine-tune 実験（**稽古場＝本体アプリ内**。拡張には入れない——
  メモリと CC-BY-SA 重み配布の両論点が解けるまで）。
- iPad 全鍵盤版（原器を硝子へ）。左手鏡像・アクセシビリティ仕上げ。
- 草モード（一筆書き）の研究実装——日本語のグライド入力は先行が総崩れの領域なので、
  稽古場で計測が立つてから拡張に入れる。

## M5 以降 — 多platform展開

**遠景だつたものが工程になつた。** macOS・Windows・Android への展開は
[cross-platform.md](./cross-platform.md) §10 が引き継ぐ:

| 段 | 内容 | 状態 |
|---|---|---|
| M5-a | 共有核 `core/`（Rust）— 旧字・五十音・**原器**・氣配・状態機械・黄金ベクトル | **済** |
| M5-b1 | Swift をベクトルに従はせる（macOS CI が検証） | **済** |
| M5-b2 | uniffi で iOS を核へ載せ替へ | Mac が要る |
| M6 | macOS 殻（IMKit）— **原器が帰る場所** | Mac が要る |
| M7-a / M7-b | Windows 殻（TSF）の骨組み / 実装 | 骨組みは**済**・実装は Windows 機が要る |
| M8 / M9 | Android 殻（IMS）／ 設定・辞書の同期 | 未着手 |

**配列も氣配も旧字確定も、もう核に在る**ので、残るのは殻を書く仕事である。

## 遠景（なほ設計だけ）

- 変体仮名 — Unicode 化済みだが IME・フォントとも未整備の領域。出すなら
  入力とフォント同梱の両方を自前で持つ必要がある（調査済み・優先度低）。
- Linux（Fcitx5 / IBus）— 核が Rust なので殻は C ABI で書ける。追加コストは小さいが優先度は低い。

## リスク表

| リスク | 兆候 | 手当て |
|---|---|---|
| メモリのサイレント kill | 既定キーボードへ勝手に戻る | 予算 36MB／瞬間 50MB（[architecture.md](./architecture.md) §4）、`preloadDictionary` 禁止、jetsam report の読み方を稽古場に文書化 |
| 審査 4.4.1 | フルアクセス必須に見える作り | 三層設計で構造的に回避（T0+T1 で成立が既定）。審査ノートに劣化動作を明記 |
| レート制限と IME の相性 | 429 頻発・体験劣化 | 明示引金のみ・デバウンス・静かな T1 退避。必要なら env で枠調整（コード不変） |
| 学習コスト（新配列） | 初日の離脱 | JoyFlick の知見（既習の再写像が学習を 1.5 倍速にする）に従ひ、楷を既定に・稽古場で行打ちへ誘導。標準フリックとの併存を妨げない |
| 縦書き描画の工数 | 候補列の実装が重い | Core Text 直描画は候補列の小矩形に限定。初版は横書き候補列でも成立（縦書きは M2 内の交換可能部品） |
| サーバ cold start | 初回変換が数十秒 | T2 は常に非同期追記。作業帯は T1 で即応し、濃墨化を待たない |
| 辞書の質 | 変な候補が上位に | `anco evaluate`＋収穫時の頻度閾値。実例主義（in_corpus 重み 0.5）が誤爆を抑へる側に働く |
| SSOT の逸脱 | Python 修正が Swift に未反映 | 生成物鮮度チェック＋パリティベクトルを CI ゲートに（M1 で敷く。後回しにしない） |

## コスト見積り

- **開発時の追加固定費: $0**（既存構成のまま。CI は GitHub Actions の macOS 分数のみ増）。
- **運用**: IME の T2 呼び出しは既存の公開枠／関係者枠・日次上限・Foundry TPM の
  三重の傘の下に入る（新しい課金経路を作らない）。明示引金の設計により、
  IME 一台あたりの `/convert` 呼び出しはチャット利用と同じ桁に収まる想定。
- **辞書ビルド**: ローカル一回（青空 300 作品の再取得＋抽出）。embedding 不要なので $0。
