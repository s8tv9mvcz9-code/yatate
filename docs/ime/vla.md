# VLA 層 — 鍵盤を行為空間として見る（気配・筆脈・滲み）

> VLA（Vision-Language-Action）をロボット抜きで住まはせる設計。ここでの読み替へは:
> **V ＝ 鍵盤といふ場面**（幾何学を持つ行為空間の知覚）、**L ＝ 文**（延伸としての言語）、
> **A ＝ 打鍵と軌跡**（連続的な制御）。身体は腕ではなく**書く手**であり、
> 「知覚→方策→行為」のループが一打ごとに回る。IME は VLA 的な機構が
> 研究室でなく生活の中で毎日動く、最も身近な舞台になり得る。
>
> 実用性が主目的ではない。**技術の内実が見えること**——モデルが次に何を期待し、
> どれほど確信し、文脈にどう染められてゐるかが、行為空間そのものの上に
> 常に表示されること——を第一の設計目標とする。

## 1. なぜ IME が VLA の舞台なのか

ロボティクスの VLA は「画像＋指示 → 行動系列」を一つの方策として学ぶ。
矢立の入力には同じ三つ組が最初から揃つてゐる:

| VLA | 矢立での実体 | 既にある土台 |
|---|---|---|
| Vision（場面の知覚） | 二行配列の幾何学。どの鍵がどこにあり、指がどこにゐるか | [layout.md](./layout.md) の行×段の地図（実装は PR #7 の `YatateCore/Gojuon.swift`） |
| Language（言語・指示） | 書きかけの文・左文脈・書き手の癖 | `/convert` と制約流（[protocol.md](./protocol.md)） |
| Action（行為） | タップ・書き下ろしスライド・草の一筆（連続軌跡） | 楷行草（[layout.md](./layout.md) §3） |
| 拡散条件付け | **情緒**。文全体の情調が方策を淡く染める | 共感覚レイヤー（`app/synesthesia.py`・13 情調） |

行打ち（[protocol.md](./protocol.md) §2）は「行為の情報量を落とし、言語側で復元する」
方式だつた。VLA 層はその双対——**言語の期待を行為空間へ射影して見せる**——を担ふ。
二つは同じ確率場の別の断面である。

## 2. 三つの見える形（内部エンジンにしない）

### 墨の気配（すみのけはひ）— 方策の知覚化

次の一打の確率分布 P(次の行為 | 文脈) を、**鍵そのものの墨の濃淡**として常時描く。
「け」と書けば ら行 が濃くなる（「けり」「けれ」の気配）。「なり」と書けば
句点「。」の鍵が濃くなる（文の終はる気配）。空の作業帯では、文語の助詞たちの鍵が
うつすら息をする——**鍵盤が静かに呼吸してゐる**やうに見える。

- 予測変換バーとの違ひ: 候補（語彙空間）ではなく**行為空間（どの鍵か）**に描く。
  モデルの期待が「手の届く場所」に直接見える。
- 段レベルの気配は**梯子の中**に描く（か行を押へた瞬間、け の段が既に濃い）。

### 筆脈（ひつみゃく）— 意図軌跡の可視化

書道で筆脈とは、字と字の間に墨は無くとも**気脈が繋がつてゐる**ことを言ふ。
矢立では、最後に触れた鍵から最有力の次の鍵へ、**淡い一画**を走らせる。
方策の argmax——モデルが「次はこちらへ」と手を差し伸べる線——であり、
ロボティクスで言ふ意図軌跡（intended trajectory）の、書の言葉による翻訳である。

### 滲み（にじみ）と結晶 — 拡散条件付けの可視化

情緒・文脈は個々の打鍵を決めない。**分布全体を淡く傾ける**——これは拡散モデルの
条件付けと同じ働き方であり、だから「拡散としての情緒」と呼ぶ。見える形:

- 入力全体の情調色（共感覚）が墨の気配に**滲む**（哀愁の文脈では気配の墨が藍鼠を帯びる）。
- 草モード（将来）では、未解消の文が**靄→楷書へ結晶する**。制約が集まるほど
  ノイズが晴れる——逆拡散の過程を、そのまま表示の言葉にする。

## 3. 見えることの原則（実用性ガード）

1. **鍵は動かさない。** 気配は墨のみ。配置・大きさの変動は筋肉記憶の敵である
   （当たり判定の Fitts 支援は任意設定・既定 OFF・上限つき）。
2. **弱信号は無地。** 分布が平らなら描かない——共感覚の「弱信号は白磁・無地」と
   同じ規約（`app/synesthesia.py` の実用性ガードのパリティ）。
3. **確信を偽らない。** 気配の濃さは正規化した確率そのもの。外れたら外れたと分かる
   （的中率は稽古場で計測——§5）。
4. **切れる。** 気配・筆脈・滲みは各々独立に OFF にできる。

## 4. 段階的な実体 — A0 / A1 / A2

### A0 — コーパス n-gram（決定的・依存ゼロ・**実装済み**）

> **現況（2026-07-31）**: A0 は Swift（`Kehai.swift`）と**共有核**（`core/src/kehai.rs`）の
> 両方に在り、**黄金ベクトル**（`core/vectors/kehai.json`）が両者の一致を機械で縛つてゐる。
> 元データの仮名 bigram も一つのファイル（`core/data/kana_bigram.txt`）から
> 両言語の表を起こす形にした——別々に収穫すると青空文庫のカタログの変化で
> 二つの表が静かにずれ、iOS と Windows で違ふ絵を描くことになるため。
>
> なほ核では**峰の同点を読み順の先着で割る**決定的な規則にしてある。
> かつての Swift 版は `Dictionary.max` ゆゑ同点で揺れ得たが、**M5-b2 で核へ載つたので消えた**。

青空文庫の旧字旧仮名テキストから**仮名連**（ルビ除去後の本文に現れる ひらがな の連なり
——助詞・助動詞・送り仮名、すなわち**文語の呼吸**そのもの）を取り出し、
仮名 bigram を数へて核の表に機械生成する（`scripts/gen_yatate_ngram.py` →
`core/data/kana_bigram.txt` → `scripts/gen_bigram_tables.py` →
`core/src/generated/kana_bigram.rs`）。**表は一枚だけ**で、全 OS の殻がそれを見る。

- 実行時は `Kehai`（気配）が bigram を行×段の行為空間へ射影する:
  P(次の仮名) を、その仮名が住む鍵（行キー・ん・句読点）へ足し込み、最大値で正規化して
  墨とする。梯子用に行内の段分布も出す。**訓練なし・端末内・ネットワーク不要**で、
  「機械で決まることは機械で」の原則のまま VLA の絵が動く。
- 限界も見える形にする: bigram は一字の記憶しか持たぬゆゑ、気配はしばしば外れる。
  それで良い——**外れる様が見えること**が A1 の動機づけである。

### A1 — 小型条件付きモデル（左文脈＋情緒）

文字レベルの小型 LM（zenz 系 90M の蒸留、または独自の数 M パラメータ）で
P(次の制約 | 左文脈, 情調ベクトル) を出す。情調 13 カテゴリの分布（`text_moods`）を
条件ベクトルとして入れることで、「拡散としての情緒」が比喩から実装になる——
同じ「け」でも、哀愁の文脈では「けり」の気配が濃く、春光の文脈では別の連なりが浮かぶ。
Core ML で拡張内に載る規模（数 MB 級）に抑へる。導入時は [architecture.md](./architecture.md)
§4 の予算表に A1 の行を立てて改訂する——jetsam 余白 10MB を黙つて食ひ潰さないこと。

### A2 — 軌跡復号（草の実体・最も VLA の原型に近い）

草モードの一筆——鍵盤上の連続軌跡——は行為の系列であり、その復号
P(文 | 軌跡, 文脈) は VLA の逆問題である。軌跡を鍵近傍の尤度列に落とし、
A1 の言語事前分布と合成して制約列へ復元する。表示は §2 の結晶——
復号の確信が上がるにつれ靄が晴れる。日本語のグライド入力は先行が総崩れの領域
（[interaction.md](./interaction.md) §9）ゆゑ、稽古場で計測が立つまで拡張には入れない。

## 5. 計測（稽古場）

- **気配の的中率**: 実際の次打鍵が墨の上位 k 鍵に入つた率（k=1,3）。A0 の素の値を
  基準線として記録し、A1 の改善を同じ物差しで測る。
- **筆脈追従率**: 筆脈の先と実打鍵の一致率。
- **視覚負荷**: 気配 ON/OFF での KSPC・確定時間・主観負荷の A/B（気配が「賑やか」に
  堕ちてゐないかの検査。§3 の原則が守られてゐれば差は小さいはず）。
- 全て端末内のみ・稽古場のみ（[interaction.md](./interaction.md) §8 と同じ規約）。

## 6. 正直な位置づけ

墨の気配が KSPC を下げる保証はない。だがこの層の眼目は効率ではなく、
**モデルの期待・確信・文脈への染まり方が、行為空間の上に隠さず見えること**にある。
予測変換バーは「モデルの答へ」を見せるが、気配は「モデルの構へ」を見せる。
道具の思考が手元に見える——それがこの舞台で VLA といふ技術を理解するといふことである。
