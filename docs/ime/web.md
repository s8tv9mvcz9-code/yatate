# web 殻 — 変換器を作らず、鍵盤だけ web に出し、手修正を覚える

> **方針**: web UI で**鍵盤のみ**実現した IME で仮名を打ち、対話的に編輯する。
> 利用者の手修正はキャッシュして、そのブラウザでは引き継がれる。

## 1. 何を作り、何を作らないか

**作らない**: かな→漢字の変換器を一から作ること。ここは一足飛びに行かない。

**作る**: 原器（縦組五十音配列）で仮名を打つところまでを web に出し、
漢字化は使ひ手が手で直す。そして**その直しを覚える**。

つまり辞書を「作る」代はりに、使ひ手に**育てさせる**。
初日から使へて、使ふほど手数が減る。T1（端末内辞書）が入つたときには、
この蓄積がそのまま利用者辞書の初期値になる——捨てる作業にならない。

!!! note "焼き付け辞書が先に入つた"
    設計時は「変換器は無い」前提だつたが、issue #4 で
    **決定的な変換（辞書引き・格子探索・文節分割）が核に入つた**
    （[artifacts.md](./artifacts.md)）。ゆゑに web 殻は初手から
    「学習」「辞書」「変換」の三つを候補として出せる。
    手修正を覚える仕組みは変はらない——辞書が当たらないところを人が埋める、
    といふ関係になつただけである。

## 2. なぜ今これが出来るのか

核（`core/`）は**依存ゼロ**なので、そのまま WebAssembly に載る。
しかも **wasm-bindgen は要らない**。核の入出力は「文字を入れる／文字列を貰ふ」だけなので、
素の `extern "C"` で足りる。

おかげで道具立ては **cargo と python3 だけ**で済み、CI は ubuntu（課金 1 倍）のまま増えない。
殻がまた一つ増えても核は一つ、といふ [cross-platform.md](./cross-platform.md) の骨格も崩れない。

```
core/ （Rust・依存ゼロ）
  └─ web/src/lib.rs  … 素の extern "C" で 17 の出口を出すだけ
        └─ yatate.wasm（約 120 KB）
              └─ yatate.js が呼ぶ（頁に頭脳は無い）
```

## 3. 鍵の取り方 — ここが肝である

ブラウザの `KeyboardEvent` には `key`（出る文字）と `code`（物理位置）がある。
**`code` を使ふ。** 理由は Windows 殻とまつたく同じで、原器は「指の位置の地図」だからである
（[layout.md](./layout.md) §1）。

`key` を見ると、JIS と US で意味が入れ替はる三鍵が壊れる。とりわけ「し」は
**刻印も物理位置も同じ**なのに配列で別物になるので、気づかぬまま「さ」が出る。
例外も警告も出ない。

| 原器 | Windows の走査符号 | ブラウザの code |
|---|---|---|
| さ | `0x28` | `Quote` |
| し | `0x27` | `Semicolon` |
| 前置シフト `^` | `0x0D` | `Equal` |
| 数字 10 鍵 | `0x02`〜`0x0B` | `Digit1`〜`Digit0` |
| 英字 20 鍵 | — | `KeyA`〜`KeyZ` |

### 地図は核が一枚だけ持つ

同じ地図を殻ごとに書けば、放つておいて必ずずれる。ゆゑに
**`core/src/kagi.rs` を唯一の出所**にした。

| 殻 | 従ひ方 |
|---|---|
| **web** | 核の表を**そのまま使ふ**（写しを持たない＝ずれやうが無い） |
| **Windows** | 自分の表を核へ照合する試験を持つ（VK は Windows 固有なので殻に残る） |

`core/vectors/kagi.json`（黄金ベクトル）が両方を縛る。
**頁は配列表すら持たない**——原器の図も `yatate_layout()` が返す表を描くだけなので、
「図と実際の打鍵がずれる」事故がそもそも起きない。

## 4. 学習の仕組み — 「直した」ことを、どう捉へるか

確定した仮名の一続きを、**読みを持つた一塊**として編輯欄へ置く。

```html
<span class="kata" data-yomi="けふ" data-taught="今日">今日</span>
```

使ひ手がこの中を書き換へると `data-yomi` は「けふ」のまま、見えてゐる字だけが変はる。
**その差分が教はつた内容そのもの**である。

- 収穫の契機は `input` の落ち着き（600ms のデバウンス）か、欄から離れたとき
- 覚えた対は `localStorage`（`yatate/manabi/v1`）に置く。そのブラウザだけで引き継がれる
- 同じ読みに複数の表記が付いたら、使つた回数の多い順に並べる
  （**消さない**。文語では「今日／けふ」を書き分ける事が普通に起きる）

### 打つてゐる最中の提案

確定の前に、いま打つてゐる仮名で候補を立てる。並びは:

1. **学んだ対**（使つた回数の多い順）— 「あなたが 3 度書いた」
2. **辞書**（`core/data/jisho.tsv` の焼き付け辞書）
3. **変換**（`bunsetsu::segment` による文節分割。二字以上のとき）
4. **仮名のまま**

`Space` で候補を送り、`Enter` で採る。
**覚えも辞書も当たらなければ何も出さない**（空の候補窓を出さない）。
候補の由来を小さく示す——どこから来た提案かが分かると、直す判断が早い。

### 確定のとき旧字は機械で決まる

これは既に核の仕事である（`kyuji::to_kyuji`）。覚えた表記に新字体が混じつてゐても、
差し込むときに旧字体へ直る。**使ひ手が旧字を覚える必要は無い。**

なほ**確定そのものは仮名を返す**（`yatate_commit`）。読みを旧字へ潰してしまふと、
覚えるべきものが失はれるからである。旧字は「表記を差し込む瞬間」にだけ掛ける。

## 5. 無通信の約束との関係

矢立は「通信するコードを持たない」を公開の約束にしてゐる（[privacy.md](../privacy.md)）。
web 版は**頁の配信そのものが通信**なので、ここは書き分ける必要がある。

| もの | どこで起きるか |
|---|---|
| 頁と wasm の取得 | 通信（初回のみ。以後はキャッシュ） |
| 打鍵・変換・旧字確定 | ブラウザの中だけ |
| 学習した対 | `localStorage` のみ。送信も同期もしない |

**約束は作文ではなくバイナリの性質として立つ。** 組み上がつた wasm には
`import` が**一つも無い**——外の世界の関数を一つも呼べないので、通信も保存も出来ない。
`web/check_wasm.py` が CI で毎回これを検める（Windows 殻の CI が実 DLL の
エクスポート表を検べてゐるのと同じ関門である）。

「そのブラウザだけ」は制約ではなく約束の一部である。端末間の持ち運びが要るなら、
[cross-platform.md](./cross-platform.md) §9-2 の A 案（書き出し／読み込み・単一 JSON）に
素直に繋がる——頁の「書き出す／読み込む」が既にそれである。

## 6. 検証をどう張るか

| 関門 | 何を捕まへるか | どこ |
|---|---|---|
| `cargo test`（core） | 原器・合成・旧字・辞書・文節 | ubuntu |
| `cargo test`（web） | C ABI・`code` からの打鍵・学習の助け | ubuntu |
| wasm ビルド | 核が web 殻に載るか | ubuntu |
| `check_wasm.py` | **出口の欠落**（頁が黙つて死ぬ）と **import の混入**（約束が破れる） | ubuntu |
| `kagi.json`（黄金ベクトル） | JIS/US の取り違へ。Windows 殻と web で地図がずれる事 | ubuntu |

web の試験は**すべて Rust 側**にある。JS には頭脳が無いので、JS を試験する対象が薄い
——これは意図した配分である（頭脳を殻に置かない設計の帰結）。

## 8. 実物を見て決めたこと

設計時に「未決」としてゐた点。**実物を動かして決めた。**

### 編輯欄の実体 — `contenteditable` を採る

`textarea` ＋別途の対応表は素直だが、位置合はせを常に自分で保たねばならない。
**読みを塊に貼り付けたまま編輯させられるのは `contenteditable` だけ**なので、そちらを採つた。
代償は癖で、実際に出たのは二つである:

1. **塊が割れる。** 塊の中で改行・貼り付けをすると、ブラウザが `span` を複製して割る。
   割れたまま収穫すると、一つの読みに半端な表記を二つ覚えてしまふ。
   → 塊に `data-id` を振り、同じ id が複数居たら繋ぎ直してから収穫する。
2. **焦点が外れると未確定が宙に浮く。** 欄の外を触つた瞬間、打つた仮名が
   どこにも属さないまま残る。
   → `blur` で**仮名のまま**確定させる。打つた仮名を捨てるのは論外だが、
     選んでもゐない候補を勝手に採るのも違ふ。

（もう一つ、`#bar` に `display: flex` を当てたせいで UA の `[hidden]` が効かず、
確定後も空の候補窓が残つてゐた。CSS に明示の `#bar[hidden] { display: none }` を足した。
いづれも実物を動かすまで見えなかつたものである。）

### 収穫の粒度 — 確定の一続きをそのまま覚える

文節単位に細かく割る案もあつたが、まづ単純な方で始める。
塊の単位＝確定の単位なので、使ひ手から見て「直した場所」と「覚えられる場所」が一致する。

### 候補の出し方 — 送り（`Space`）で足りる

番号直指定は入れてゐない。候補が四つを超えることが稀だからである
（学習・辞書・変換・仮名のまま）。増えたら考へる。

### 記号・小書き — 原器で未定なので、ここでも発明しない

原器に置き場が定まつてゐないものは、web 殻でも決めない。
`、` `。` は氣配の分布には現れるが、鍵へは流してゐない。
