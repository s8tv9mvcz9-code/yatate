# 矢立（やたて）— AI ネイティブ文語 IME 設計書

> **bungo-rag の第4のクライアント**として、iOS 上で動く文語（旧字旧仮名・歴史的仮名遣ひ）専用のカスタムキーボードを設計する。
> 矢立とは、筆と墨壺を一つに納めて腰に差した携帯筆記具のこと。文机（＝本体アプリ）に対する、懐中の書き道具である。

## なぜ IME か

このリポジトリは既に答へを半分持つてゐる。`POST /convert`（`app/convert.py` + `app/kana.py`）は、
市販 IME が構造的に扱へない「歴史的仮名遣ひの仮名 → 旧字旧仮名の漢字混じり文」を、

1. **読みの完全被覆**といふ機械検査可能な不変条件（`"".join(yomi) == 入力`）で LLM の脱落・捏造を構造的に検出し、
2. 青空文庫コーパスの**実例**と**共感覚（情調）**で候補を並べ替へ、
3. 新字体→旧字体を決定的トランスデューサ（`app/kyuji.py`）で機械確定する

——文節単位の候補構造として返す。これは既に **IME の変換エンジンの契約そのもの**である。
欠けてゐるのは入力面だけだ。チャット UI の中でしか使へない変換器を、OS の文字が入るあらゆる場所
（メール・メモ・SNS）へ持ち出す器が、カスタムキーボード拡張である。

## 設計思想 — AI ネイティブとは何か

既存の IME は「確定した文字列を最速で入力する装置」として設計されてきた。キーの一打は一文字
（一モーラ）に対応し、曖昧さは即座に解消されなければならない。フリック入力の 12 キーも、
ローマ字入力も、この前提の上にある。

矢立はこの前提を捨てる。**入力とは、書き手が発する制約の流れ（constraint stream）であり、
文はその制約を満たす解として、コーパスの証拠と言語モデルの協働で結晶する。**

四つの柱:

1. **入力は制約流である。** 一打が運ぶ情報量を書き手が選ぶ。行だけ示して段を委ねてもよいし
   （「な行の何か」）、一字を完全に指定してもよい。精密さの度合ひを書体になぞらへて
   **楷・行・草**の三態と呼ぶ（[layout.md](./layout.md)）。未確定の部分は淡く表示され、
   制約が集まるにつれ楷書の字面に結晶する。
2. **変換は校合（けうがふ）である。** 候補は頻度順ではなく、青空文庫の実例（`in_corpus`）・
   入力全体の情調との親和度（`mood`）・モデルの事前分布の合成で並ぶ（`app/kana.py` の
   `rank_candidates`、重み 0.5 / 0.35 / 0.15）。各候補は出典を持ち、UI はそれを示す。
   変換とは辞書引きではなく、先人の文例との突き合はせである。
3. **機械で決まることは機械で決める。** 読みの被覆検査・旧字体の確定・仮名遣ひの正規化は
   決定的な純関数であり、LLM には任せない。LLM が任されるのは「どの漢字を当てるか」といふ
   本質的に文脈依存な判断だけ。この分業は `app/kana.py` の docstring に既に明文化されてをり、
   IME はそれを端末内に移植する。
4. **IME は文語の師匠である。** 候補の出典チップに触れれば原文の一節が開く。誤つた仮名遣ひは
   黙つて直すのではなく、なぜさう綴るのかを一行で示せる。入力するたびに文語が身につく
   ——道具が使用者を育てる。

## 縦書きといふ座標系

日本語の文はもともと上から下へ、行は右から左へ流れる。矢立は
この組方向を入力体験の座標系として採用する。着想の原点は、使用者が約 10 年使ひ込んできた
自作 PC 配列（五十音を縦書きの紙面としてキーボードに折り畳んだもの——詳細は
[layout.md](./layout.md)）にある。モバイルでは、行（ぎゃう）キーを縦書き二行に並べ、
段の選択は**指を下へ滑らせる**——あいうえおの段梯子を、文字通り縦に書き下ろす所作で行ふ。
濁点は字の右肩に打たれるものだから、**右への逸らしが濁点**になる。操作の一つ一つが
和文組版の身体感覚と同型になるやう設計する。

## スコープと非スコープ

- **対象**: iOS カスタムキーボード拡張（iPhone 主対象・iPad は全鍵盤版）。本体アプリ
  （既存 BungoRag app）は設定・稽古場（練習モード）・辞書管理を担ふ。
- **非対象（当面）**: macOS IMKit 版（設計は共有可能、[roadmap.md](./roadmap.md) の遠景に記載）、
  Android IMS 版（契約はクライアント非依存なので追随可能）。
- **制約**: キーボード拡張はフルアクセス無しでも成立しなければならない（審査要件・思想の両面）。
  ゆゑに端末内だけで実用になる決定的核＋辞書層を持ち、サーバ校合（`/convert`）は
  フルアクセス許可時の**上乗せ**とする（[architecture.md](./architecture.md)）。

## 名について

- **矢立（Yatate）** — キーボード拡張本体。ターゲット名 `YatateKeyboard`。
- **楷・行・草** — 入力確度の三態。「行」は かな の行（ぎゃう）と行書の掛詞である。
  行だけ打つ入力法を**行打ち（ぎゃううち）**と呼ぶ。
- **二行（ふたくだり）配列** — モバイル配列。縦書き二行に見立てた 2×5 の行キー。
- **縦組五十音配列（原器）** — 使用者考案の PC 配列。iPad 全鍵盤版の底本。
- **墨の気配・筆脈（ひつみゃく）・滲み** — VLA 層の可視化語彙。次の一打の分布を鍵の墨の
  濃淡で、最有力の一手への気脈を淡い一画で、情緒の拡散条件付けを墨色の滲みで描く
  （[vla.md](./vla.md)）。
