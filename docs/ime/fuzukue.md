# 文机（ふづくえ）モード — 紙面ステートマシン（macOS 版の先行像）

> 大画面（iPad・macOS）は「鍵盤を大きくする」ためにあるのではない。
> フリックを横に並べ直すのは鍵盤の拡大にすぎぬ。文机モードは**画面全体を
> 五十音の紙面とし、紙面そのものをステートマシンにする**——マスが状態、
> 指の運びが遷移、一筆が語。macOS 版（IMKit）の本命 UI をこの形と定め、
> まづ **iOS フル画面（本体アプリ内の一章）でエミュレート**する。
> 本体アプリ内ゆゑ拡張の制約（メモリ・フルアクセス・ハードキー不可）が消え、
> 実装コストは小さい。

## 1. 紙面 — 原器の完全形

キーボード拡張の二行配列は、狭さゆゑに「行キー＋梯子」へ畳んだ姿だつた。
紙面にはその必要がない。**十の行が右から左へ全て開く**——五十音表を
縦書きの頁として、そのまま敷く:

```
 ん   わ  ら  や  ま  は  な  た  さ  か  あ   ｜文
 、   ゐ  り     み  ひ  に  ち  し  き  い   ｜が
 。      る  ゆ  む  ふ  ぬ  つ  す  く  う   ｜こ
 空   ゑ  れ     め  へ  ね  て  せ  け  え   ｜こ
 ⌫   を  ろ  よ  も  ほ  の  と  そ  こ  お   ｜に立つ
（機能縁）    （十行の紙面・右から左）      （書かれた文・縦書き）
```

- 前置シフトは不要になり、**ゐ・ゑも常設のマス**を持つ。原器が目指した
  「五十音の地図の上に指を置く」ことの、制約なしの実現形である。
- 書かれた文は紙面の右端に**縦書きで立つ**。頁の第一行に書いてゐる、といふ見立て。

## 2. 空間ステートマシン

形式的には: 状態集合 S ＝ {中立} ∪ 仮名マス ∪ 修飾 ∪ 機能縁。遷移は指
（macOS ではポインタ）の**マス進入**で起き、**持ち上げが切れ**（stroke break）である。

| 所作 | 遷移 | 意味 |
|---|---|---|
| マスに触れて離す | 中立→マス→中立 | 一字（楷） |
| 触れたまま次のマスへ | マス→マス→… | **連綿**——一筆で複数字 |
| マス内で右へ小さく鉤（かぎ） | マス→濁 | 濁点（書き下ろしの右肩逸らしと同じ作法） |
| 左へ鉤 | マス→半濁・小書き | 同上 |
| 行の頭だけ掠めて次へ | 行状態のみ | 段を委ねる（行打ちの紙面版） |
| 持ち上げ | →中立 | 切れ。楷行草は**筆が紙を離れる頻度**として統一される |

楷行草の再解釈がこの設計の要である: 鍵盤では「モード切替」だつた三態が、
紙面では**同じ状態機械の上の運筆の癖**にすぎなくなる。一字ごとに持ち上げれば楷、
掠めれば行、離さなければ草——書き手は宣言せずに、ただ書く速さを変へるだけでよい。

進入の確定には滞留ガード（数十 ms／数 pt）を置き、マスを**通過しただけ**の誤発火を
抑へる。それでも残る曖昧さは A2（[vla.md](./vla.md)）の軌跡復号が受け持つ——
経路全体を尤度列に落とし、コーパスの言語事前分布と合成して文を復元する。
**紙面が広くマスが大きいほど軌跡復号は易しくなる**。文机は A2 の自然な住処である。

## 3. 気配と筆脈の本領

鍵盤では行キー単位に潰れてゐた墨の気配が、紙面では**マス単位**で滲む
（「け」の後、紙面のあちこちで「れ」「り」「ふ」のマスだけが濃くなる）。
筆脈は紙面を横切る一画となり、連綿の次の一手を目が先に知る。

先行との差を明記する: **Dasher** は言語モデルの確率で空間そのものを歪めて
文字を流し込む方式、**Quikwriting** は持ち上げない zone 遷移入力の古典である。
文机は両者の子でありながら、**紙面を動かさない**——確率は墨の濃淡だけで語り、
マスの位置と大きさは不変（「鍵は動かさない」原則——[vla.md](./vla.md) §3——の継承）。
筋肉記憶が育つ余地を確率表示と両立させるのが、書の道具としての矜持である。

## 4. macOS への写像

| 層 | iOS フル画面（先行像） | macOS（本命） |
|---|---|---|
| 紙面 | 本体アプリの「文机」タブ | IMKit 入力ウィンドウ／専用エディタ |
| 運筆 | 指 | トラックパッド・ペン（ポインタ軌跡） |
| 硬鍵盤 | ―（拡張では不可） | **原器そのまま**（IMKit はキーイベントを拾える） |
| 変換 | `/convert`（本体アプリゆゑ自由に叩ける） | 同じ契約 |

YatateCore は最初から macOS を platforms に含めてある（Package.swift）。
文机ビューの SwiftUI コードは両 OS でほぼ共有できる。

## 5. 最小実装（PR #7 同梱の草稿）

本体アプリに「文机」タブを足し、次だけを実装する:

- 十行＋機能縁の紙面（`YatateCore/Gojuon` から生成。ゐゑ常設）
- **進入確定の決定的ステートマシン**（滞留ガードつき・連綿の軌跡を薄墨で描画）
- マス単位の墨の気配（`Kehai` の行×段射影をセルへ展開）と紙面を渡る筆脈
- 右端の縦書き文（確定で旧字化——`toKyuji`）

未実装（設計のみ）: 濁点・小書きの鉤、行掠め、A2 軌跡復号、macOS ターゲット。
滞留ガードの時定数と誤発火率は稽古場の計測項目（[vla.md](./vla.md) §5 と同じ物差し）。
